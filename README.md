# [프로젝트 이름]

> 수원문화재단의 홈페이지에서 다양한 문화프로그램을 한눈에 보고 쉽게 예약할 수 있도록 개선한 웹사이트

## 1. 링크

- **Live Demo**: https://cyedam.github.io/figma-practice/
- **GitHub**: https://github.com/cyedam/figma-practice
- **Figma 디자인**: https://www.figma.com/design/vHdYOApUUHSwrm6FWCcFD4/%EC%88%98%EC%9B%90%EB%AC%B8%ED%99%94%EC%9E%AC%EB%8B%A8-%EA%B0%9C%EC%84%A0?node-id=8820-24475

## 2. 프로젝트 정보

- **제작 기간**: 2026.11.06 ~ 2026.11.11 (06일)
- **담당 역할**: 개인 프로젝트 (기여도 100%)
- **담당 범위**: Figma 개선 디자인 → 바이브코딩 구현 → GitHub Pages 배포

## 3. 사용 기술

- **React, Vite**: 메인 → 프로그램 목록 → 신청 → 신청 조회까지 여러 화면을 주소로 나눠 이동하기 위해 사용하였고, 버튼·입력창·카드 같은 Figma 컴포넌트를 그대로 React 컴포넌트로 옮겨 여러 화면에서 재사용하고, 빠르게 개발·빌드하기 위해 사용
- **GitHub Pages**: 무료 배포, main 브랜치에 push하면 자동으로 빌드·배포
- **Figma**: 모바일·태블릿·데스크탑 3가지 화면 폭에 따른 디자인 개선
- **Claude**: 화면 구현을 위한 바이브 코딩에 사용

## 4. 주요 기능

- **프로그램 통합 조회**: 카테고리 탭·검색·필터로 문화프로그램을 한 화면에서 찾고, 검색 결과 건수를 표시
- **실수 방지 신청 흐름**: 제출 직전 입력 내용을 다시 보여 주는 '확인·확정' 모달, '목록으로'를 누르면 작성 내용이 사라진다고 알려 주는 경고 모달
- **입력 편의성**: 비밀번호 표시/숨김 토글, 인원 선택 카운터, 달력으로 날짜 선택
- **신청 내역 조회와 대체 인증**: 비밀번호를 잊어도 문자인증·전화문의로 조회하고 비밀번호를 재설정
- **반응형 레이아웃**: 모바일(768px 미만)·태블릿·데스크탑(1440px 이상)마다 Figma 디자인에 맞춘 화면, 모바일에서는 모달을 바텀 시트로 구성하여 기기별 편의성 부여

## 5. 트러블슈팅

### 이슈 1: 화면 폭마다 신청 완료 후 흐름이 다름

- **문제**: 데스크탑은 '최종 신청하기' 후 완료 모달이 뜨는데, 모바일·태블릿은 별도 완료 화면으로 넘어가 같은 화면이지만 통일되지 않음
- **원인**: 화면 폭에 따라 완료 안내 방식을 다르게 만들어 두었음
- **해결**: 모든 화면 폭에서 완료 모달을 띄우도록 통일하고, 모바일에서는 엄지로 다루기 쉽게 바텀 시트로 표시

### 이슈 2: 다른 화면으로 이동해도 스크롤이 중간에 머묾

- **문제**: 이전 화면에서의 스크롤 상황이 다음 화면에도 적용되어, 다음 스텝으로 이동 시 중간 화면이 보임
- **원인**: 화면이 바뀌어도 브라우저가 새 페이지로 인식하지 않아 스크롤 위치가 그대로 남음
- **해결**: `useScrollToTop` 훅을 만들어 버튼·링크로 이동하면 맨 위로, 브라우저 뒤로·앞으로 가기는 원래 보던 위치로 되돌리도록 처리

## 6. AI 활용 방식

- **맡긴 일**: Figma 화면을 React 컴포넌트와 화면으로 구현, 반응형 레이아웃, 모달·화면 이동 같은 동작 구현, GitHub Pages 배포 설정
- **핵심 프롬프트**: "인풋창에서 오류가 나면 바로 오류를 보여주고 화면이 오류창을 포커스해줘", "다른 화면으로 이동하면 맨 위부터 보이게 하고, 뒤로 가기는 보던 위치로 돌아가게 해 줘"

## 7. 회고

- **배운 점**:
  - Figma에서는 화면 모양만 보여 줄 수 있어 표현에 한계가 있었던 입력 오류 검사, 입력칸 아래 인라인 오류 표시, 오류가 난 칸으로 바로 이동하기, 검색 기능을 실제로 동작하게 구현해 볼 수 있었다.
  - Figma에서는 모바일·태블릿·데스크탑 3가지 크기만 디자인했지만, 실제 브라우저는 폭이 계속 바뀌기 때문에 패딩값이나 그외에 증감하는 여백을 어색하지 않게 구성할 수 있게 되었다.
  - AI에게 "무엇을, 어느 화면에서, 어떻게 동작하게" 할지 구체적으로 설명할수록 원하는 결과가 나왔고, 디자인 의도를 말로 정확히 전달하는 연습이 되었다.
- **아쉬운 점**:
  - 실제 브라우저에서 확인해 보니 Figma에서는 잘 보이지 않던 레이아웃 크기 문제가 드러났다. 헤더 유틸리티 영역의 높이(48px)가 데스크탑에서는 좁아 보였고, 모바일·태블릿에서도 배너에 비해 헤더가 좁아 화면이 불균형하게 느껴져 헤더 유틸리티 높이를 12px씩 늘려 가시성을 확보했다.
  - 배너 원본 이미지가 세로형으로만 준비되어 있어, 가로로 넓은 데스크탑 화면에서는 이미지가 잘려 보였다. 화면 비율별로 이미지를 따로 준비했다면 더 완성도 있게 보였을 것이다. 다음 홈페이지 제작 시 이미지의 사이즈를 다양하게 준비해 반응형에도 깨지지 않도록 하겠다.
