# 수원문화재단 통합 온라인접수 개선

요구사항의 원본은 `docs/PRD.md`다. 이 문서와 PRD가 다르면 임의로 판단하지 말고 사용자에게 질문한다.

## 1. 사용자

### 만드는 사람
- 코딩 초보자가 만드는 서비스다.
- 설명은 한국어로, 전문 용어는 쉬운 말로 풀어서 한다.
- 무엇을 왜 바꾸는지 먼저 짧게 설명하고, 직접 실행하고 확인할 방법을 알려 준다.
- 복잡한 구조보다 읽고 이해하기 쉬운 코드를 우선한다.

### 서비스 이용자
- 문화 프로그램을 검색하고 신청하려는 사람이다.
- 대표 이용자는 디지털 사용이 서툰 68세 이용자다.
- 이 이용자가 겪은 불편:
  - 알림창을 닫으면 오류 칸을 찾기 어렵다.
  - 실수로 취소하면 작성 내용이 모두 사라진다.
  - 제출 후 오타를 발견하면 전화로 문의해야 한다.
- 핵심 목표는 한 번의 진입으로 신청을 끝내는 것이다.

## 2. 기술 스택 (변경 금지)

- React
- Vite
- JavaScript
- 기본 CSS
- 화면 이동: react-router (사용자 승인 후 설치)
- 린터: oxlint

아래 작업은 사용자의 승인 없이 하지 않는다.
- TypeScript, CSS 프레임워크, UI 라이브러리 도입
- 새 패키지 설치
- 위 기술의 교체 또는 빌드 설정 변경

자주 쓰는 명령어:

```powershell
npm run dev      # 개발 서버 실행
npm run build    # 배포용 빌드
npm run lint     # 코드 검사
```

## 3. 디자인 규칙

### 디자인 구현 방식
- 디자인은 추후 Figma MCP를 통해 구현한다.
- 색상, 글꼴, 크기를 임의로 정하지 않는다. Figma 값이 없으면 사용자에게 질문한다.
- 반응형 상세 디자인(컨테이너 최대 너비, 좌우 여백, 컴포넌트별 변화 등)은 구현 단계에서 사이즈별 Figma 링크로 전달받는다.

### 반응형
- 모바일: ~767px
- 태블릿: 768px ~ 1439px
- 데스크탑: 1440px ~
- 모바일 우선으로 작성한다. 기본 스타일은 모바일이다.
- 미디어쿼리는 `min-width: 768px`와 `min-width: 1440px`만 사용하고, 임의의 px 값을 추가하지 않는다.

### 단위
- 레이아웃 너비는 %를 사용하고, 고정 px 너비는 지양한다.
- 폰트 크기와 간격(padding, margin, gap)은 rem을 사용한다.
- em은 사용하지 않는다.

### 화면 규칙
- 제출 버튼은 주요색, '목록으로' 버튼은 윤곽선으로 구분한다.
- 오류 메시지는 입력 필드 바로 아래에 두고, 오류가 해소될 때까지 유지한다.
- 확인·확정 모달과 파기 경고 모달은 현재 작업을 잃지 않는 선택지를 기본으로 한다.
- 터치 가능한 요소는 모바일에서 누르기 편한 최소 크기를 확보한다. 수치는 구현 단계에서 Figma 기준으로 확정한다.
- 모바일에서도 읽기 편한 최소 폰트 크기를 유지한다. 수치는 구현 단계에서 Figma 기준으로 확정한다.

### 문구와 접근성
- 웹 접근성 기준은 KWCAG 2.2다.
- 버튼 이름은 '목록으로'처럼 이동 결과가 드러나게 쓴다.
- 오류 문구는 무엇이 잘못되었는지와 어떻게 고치는지를 함께 알린다.
- 입력 규칙은 입력 전에 안내한다(예: 숫자 4자리).
- 화면 낭독기가 오류를 즉시 읽도록 `aria-live`를 적용한다.

## 4. 서비스 구조

### 이용 흐름

```text
신청서 작성 → 입력 오류 정정 → 취소/초기화 조작 → 제출 및 확정 → 제출 후 확인
```

메뉴 경로: 메인 → 열린시설 → 통합 온라인접수

### 기능과 우선순위
우선순위가 높은 기능부터 구현한다. 상세 요구사항은 `docs/PRD.md` 4장을 따른다.

| 우선순위 | 기능 | 내용 |
| --- | --- | --- |
| P1 | FR-2 제출 전 확인·확정 | 바로 접수하지 않고 입력 정보를 모달로 먼저 보여 준다. |
| P1 | FR-3 작성 내용 파기 방지 | '목록으로'를 누르면 경고 모달을 먼저 표시한다. |
| P1 | FR-4 입력 오류 처리 | 오류 필드로 초점을 옮기고 메시지를 유지하며 입력값을 보존한다. |
| P1 | FR-5 버튼 위계 분리 | 제출은 주요색, 목록으로는 윤곽선으로 구분한다. |
| P2 | FR-6 입력 폼 및 비밀번호 | 규칙 사전 안내, 표시/숨김, 붙여넣기 허용, 찾기/재설정을 제공한다. |
| P2 | FR-7 대체 인증 수단 | CAPTCHA 외 대체 인증 수단을 보장한다. |
| P3 | FR-8 결과 조회 일관성 | 완료 안내와 실제 조회 로직을 일치시킨다. |
| P4 | FR-1 프로그램 조회 | 카테고리 탭, 건수 표기, 0건 처리, 검색 결과와 키워드 강조를 제공한다. |

### 현재 파일 구조

```text
docs/PRD.md          요구사항
index.html           HTML 진입 파일
src/main.jsx         앱 시작점 (BrowserRouter로 화면 이동을 켬)
src/App.jsx          주소별 화면 연결 (Routes)
src/index.css        전역 기본 스타일 (styles 폴더의 파일을 불러옴)
src/styles/          tokens.css(디자인 토큰), reset.css, base.css
src/assets/icons/    아이콘
src/assets/images/   이미지
src/hooks/           화면이 아닌 공용 기능 (useIsMobile: 모바일 폭인지 알려 줌)
src/components/      컴포넌트 (종류별 폴더)
  banner/            메인 배너, 뉴스레터 배너
  button/            버튼, 조회버튼
  calendar/          달력
  card/              카드, 뱃지, 정보 목록, 박스
  input/             입력 칸, 비밀번호, 인원, 체크박스, 드롭다운
  layout/            헤더, 위치 탭, 화면 아래 버튼 영역, 푸터
  menu/              탭, 데스크탑·모바일 메뉴
  modal/             모달, 시트
  search/            검색영역, 검색 칸, 검색 건수
src/screens/         화면 (컴포넌트를 조립한 페이지)
  ScreenLayout       화면 공통 틀 (헤더, 위치 탭, 아래 버튼, 푸터, 전체 메뉴)
  *Screen            화면별 파일
  programData.js     프로그램 목록과 안내 문구
  scheduleData.js    신청 일정
  validation.js      입력값 검사
```

화면 주소:

| 주소 | 화면 |
| --- | --- |
| `/` | 메인 |
| `/programs` | 프로그램 목록 |
| `/apply` | 신청 (`?mode=waitlist`면 대기 신청) |
| `/apply/complete` | 신청 완료 |
| `/lookup` | 접수 조회 |
| `/lookup/result` | 신청 내역 |
| `/lookup/sms` | 문자인증 |
| `/lookup/reset` | 비밀번호 재설정 |

## 5. 안전 규칙

### 질문 먼저
- 모르거나 애매한 부분은 추측하지 말고 사용자에게 질문한다.
- PRD에 "추가 확인 필요"로 표시된 항목은 임의로 정하지 말고 사용자에게 질문한다.
- 요청 범위를 벗어나는 수정이 필요하면 먼저 알리고 승인을 받는다.
- 패키지 설치(npm install) 전에 이유를 설명하고 허락받는다.
- 한 번에 여러 화면을 수정하지 않고 요청한 범위만 작업한다.
- 에러가 나면 임의로 우회하지 말고 원인을 먼저 설명한다.

### 파일과 Git
- 파일 삭제, 폴더 구조 변경 전에는 반드시 먼저 물어본다.
- 파일이나 폴더를 삭제하거나 덮어쓰기 전에 대상을 확인하고 사용자에게 알린다.
- Git 커밋과 푸시는 사용자가 요청할 때만 한다.

### 개인정보와 보안
- 이름, 연락처, 비밀번호는 콘솔에 출력하지 않는다.
- 비밀번호, API 키 같은 비밀 값을 코드에 직접 쓰지 않는다.
- 실제 개인정보를 예시 데이터로 쓰지 않는다.

### 완료 전 확인
- 코드를 바꾸면 `npm run build`와 `npm run lint`를 실행한다.
- 실패하거나 확인하지 못한 항목은 숨기지 말고 그대로 알린다.
